# Spec format

The spec is `spec.json`, created by `init`.
You fill in `summary`, `ignore`, `flows`, `steps`, and `decisions`.
The script owns `repo`, `base`, `head`, `progress`, `watchouts`, `notes`, and each step's `seen` field; change them only through its commands.

Write prose fields in plain words.
Backticks become inline code on the map.

```json
{
  "title": "Budgets v1",
  "summary": "One or two sentences: what the change lets a user do.",
  "ignore": [
    { "pattern": "frontend/package-lock.json", "reason": "lock file, generated by npm" }
  ],
  "flows": [
    {
      "id": "A",
      "title": "Set a monthly limit",
      "trigger": "A user saves a limit in the budget dialog.",
      "actors": [
        { "id": "dialog", "label": "BudgetLimitDialog", "sub": "budget-limit-dialog.ts" },
        { "id": "api", "label": "BudgetsApi", "sub": "budgets-api.ts" },
        { "id": "ctl", "label": "BudgetController", "sub": "BudgetController.java" },
        { "id": "db", "label": "PostgreSQL", "sub": "budget_limit" }
      ],
      "messages": [
        { "from": "dialog", "to": "api", "label": "setLimit(categoryId, amount)", "step": "S1" },
        { "from": "api", "to": "ctl", "label": "PUT /api/budgets/{categoryId}", "step": "S3" },
        { "from": "ctl", "to": "db", "label": "INSERT budget_limit", "step": "S6" },
        { "from": "ctl", "to": "dialog", "label": "200 BudgetResponse", "kind": "return" }
      ]
    }
  ],
  "steps": [
    {
      "id": "S1",
      "flow": "A",
      "file": "frontend/src/app/features/budgets/budget-limit-dialog.ts",
      "lines": "40-62",
      "depth": "read",
      "title": "Save handler",
      "what": "Validates the amount, calls `setLimit`, and closes the dialog on success.",
      "decisions": ["D2"]
    }
  ],
  "decisions": [
    {
      "id": "D1",
      "title": "A limit is stored per month, not once per category",
      "chosen": "One `budget_limit` row per category and month.",
      "alternative": "One row per category, applied to every month.",
      "why": "Lets a user change a limit without rewriting history. Null when unknown.",
      "steps": ["S6", "S9"]
    }
  ]
}
```

## Fields

- **ignore**: glob patterns (`*`, `**`) for changed files nobody needs to read: lock files, generated clients, snapshots, binaries.
  Every entry needs a reason; the map shows it.
- **flows**: one per thing a person or system triggers.
  Put tests, migrations, and config that serve no single flow in their own flow (for example `"id": "T", "title": "Tests"`) with empty `actors` and `messages`.
- **actors**: the boxes of the sequence diagram, left to right in layer order (UI, client, API, service, repository, database or external system).
  `label` is the class, component, or function name; `sub` is the file name or table.
- **messages**: the calls, top to bottom in the order they run.
  `label` is what passes: a method call, an HTTP method and path, a SQL verb and table.
  `kind: "return"` draws a dashed arrow.
  `step` links the arrow to the step that holds that code.
  A message from an actor to itself draws a loop.
- **steps**: in walk order, which is the order the code runs.
  `lines` is `"10-42"`, `"10-22, 30-35"`, `"all"` (the whole file), or `"deleted"` (a removed file).
  `depth` is `read` or `skim`.
  A read step is 25 lines or fewer; `check` rejects one over 40.
- **decisions**: `why` is null when the code, comments, ticket, and conversation do not say; the map then shows "Unknown: decide whether you agree".
